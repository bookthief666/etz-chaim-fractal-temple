# M4.15.1 — Realm Ignition Guard

## Physical trigger

Samsung Fold QA of hosted M4.15 reproduced an effectively black Tiphareth realm while the QA overlay still reported:

- phase `REALM`
- shader family `dedicated-solar-tiphareth`
- lifecycle `running`
- roughly 60–67 FPS
- zero WebGL context losses, restorations, or renderer remounts

That evidence rules out the old automatic-remount/context-loss failure as the sole explanation. M4.15 only proved that the JavaScript realm module had loaded; it did not promote WebGL driver shader compile/link failures into the lifecycle or QA surface.

## M4.15.1 hardening

1. `RendererGuard` now captures Three.js `renderer.debug.onShaderError` and promotes program/vertex/fragment driver logs into the existing program-failure lifecycle.
2. `FractalRealm` retains a deliberately tiny deterministic analytical compatibility renderer during the lazy-program compiler/ignition window. If the requested shader is rejected by the GPU, continuity remains visible instead of exposing the WebGL clear color.
3. The compatibility renderer is not a replacement for the canonical realm. Healthy requested realm programs remain visually authoritative and the fallback unmounts after the bounded seating interval.
4. Low-quality ignition now begins when the requested realm program actually becomes available, rather than when the React shell first mounts. Slow dynamic imports therefore cannot silently consume the ignition interval before the GPU sees the expensive program.
5. Runtime verification asserts compiler telemetry, compatibility continuity, deterministic fallback behavior, and preservation of all existing M4.15 topology/phase/shader invariants.

## Release rule

This patch targets `develop` only until physical Fold QA confirms that Tiphareth and several other Sephiroth enter visible recursive space without an unexplained black frame. `main` remains the physically accepted/stable line until that confirmation.
