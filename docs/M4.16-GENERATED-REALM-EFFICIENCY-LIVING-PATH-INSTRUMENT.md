## M4.16A — generated realm efficiency

### Confirmed source defect

The audit confirmed the suspected generated-shader inefficiency. The previous generated fragment assembled a combined `mapFields()` result containing both physical distance and decorative glyph distance. `mapScene()` selected the physical component from that combined result. Consequently:

- each normal probe evaluated the decorative glyph field even though the normal depends only on physical geometry;
- every raymarch step evaluated the decorative field;
- deterministic rebasing/domain work was repeated between the physical and glyph queries.

Malkuth and Tiphareth already demonstrated the correct principle: physical distance and emissive decoration are independent workloads.

### Generated-program redesign

The eight generated realms now assemble these distinct stages:

1. `createRealmDomain()` computes the bounded deterministic domain once per fragment.
2. `mapPhysicalLocal()` evaluates structural distance.
3. `mapGlyphLocal()` evaluates decorative/emissive distance.
4. `calcNormal()` calls only `mapPhysical()`.
5. The raymarch samples physical distance at every active step and glyph distance on alternating steps.
6. Glyph energy uses a compensated accumulation coefficient so cadence reduction does not simply halve emissive presence.

Realm source generation also selects only the sacred-geometry and palette functions required by the requested kernel. It does not reintroduce a runtime `uRealmKind` dispatcher and does not prewarm programs.

### Kether exact-cost pass

Kether retains its accepted primary tesseract frame, crown rings, recursively nested frames, depth-stage crown cells, luminous source, and original quality/depth gates. The `uQuality >= 0.68` third nested-frame gate and the `uDepthStage > 1.5 && uQuality > 0.52` crown-cell gate are unchanged.

The generated Kether kernel now:

- receives four compact phase bases computed once per frame on the CPU;
- combines those bases algebraically for the fixed nested-frame offsets;
- replaces repeated per-SDF trigonometric rotations with basis rotation;
- unrolls the fixed two-frame nesting while preserving its exact geometry;
- keeps physical and glyph basis families separate.

A deterministic 2,000-sample numerical comparison of the original and basis-composed rotations produced a maximum component error of approximately `1.22e-15`, within floating-point roundoff. This is an algebraic optimization, not a lower-detail Kether.

## M4.16B — living 22-path instrument

### Layer separation

The path system now keeps four independent authorities:

| Layer | Owner | Meaning |
|---|---|---|
| Topology | `treeTopology.js` | The canonical 22 edges |
| Documentary | `hermeticPaths777.js` | Letters, cosmic attributions, Tarot, joins, provenance |
| Interpretive visual grammar | `pathVisualGrammar.js` | Original deterministic motion mathematics |
| Operative capability | `pathOperators.js` | The two implemented reversible metamorphoses |

`pathVisualGrammar.js` explicitly marks its output as interpretive. It reads documentary attribution to choose a presentation family but does not state that historical sources prescribed the animation. No Earth path was invented and no documentary record was mutated.

The family distribution is exactly:

- Elemental: 3 — Air, Water, Fire;
- Planetary: 7;
- Zodiacal: 12.

Each path receives a stable signature from its path identity, key scale, and documented category. Elemental paths use different propagation equations; planetary paths vary orbit, epicycle, axial, and conjunction behavior; zodiacal paths vary segmentation, modality, polarity, mirroring, and phase gates. These differences are mathematical, not color-only or phase-only.

### Renderer cost model

The previous presentation created one `useFrame` callback and up to five visible meshes per `PathSegment`, repeated across 22 paths. M4.16 replaces the visible path layer with:

- one shared clock;
- two instanced draws for all 22 paths (core and halo);
- deterministic per-instance motion, signature, interaction-state, direction, and color attributes;
- shared geometry and shared materials.

`PathSegment` remains responsible for the wide invisible hit cylinder and documentary inscription only when the path is relevant. This retains interaction clarity without paying for 22 independent animation loops.

Hebrew letters remain actual Unicode Hebrew with `lang="he"` and `dir="rtl"`. The existing local browser font stack cannot guarantee a GPU Three-text Hebrew atlas without adding a fragile external font dependency, so inscriptions use Drei's transformed, sprite-facing world-space HTML. They remain attached to the 3D path, ignore unrelated pointer input, and strengthen with resonance/selection.

### Interaction and operator readiness

The renderer distinguishes dormant, connected/resonant, inspectable, selected, and operative states. A selected operative path receives a restrained counter-current unavailable to documentary-only edges.

Only these two reversible operators remain traversable:

- Geburah ↔ Tiphareth — fivefold to sixfold harmonization;
- Yesod ↔ Malkuth — phase to crystal condensation.

Future operators can be added to `PATH_OPERATORS` without rewriting topology, documentary records, or the shared path renderer. The remaining twenty paths are not falsely promoted to metamorphoses.
