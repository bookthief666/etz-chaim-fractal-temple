# M4.11 — Living Tree Instrument

## Scope

M4.11 continues the accepted family-UI track after the M4.10 runtime/Malkuth stability lock. It deliberately does **not** resume procedural sonification and does not alter the canonical Tree topology, provenance-bearing documentary layers, path mathematics, or any of the ten raymarched realm kernels.

The goal is to make the macro Tree itself behave like a living astrolabe rather than a diagram behind menus.

## Changes

### 1. Interpretive astrolabe field

A new `TreeInstrumentField` sits behind the canonical graph. It contains extremely faint pillar guide filaments, elliptical astronomical rings, geometric cross-lines, and two slow whole-Tree breaths. The layer is explicitly presentation grammar only: it does not add nodes, edges, path attributions, or historical claims.

### 2. Graph-aware resonance

Focusing a Sephirah no longer dims every other sphere uniformly. Directly connected Sephiroth remain partially luminous, while non-neighbors recede. The topology therefore becomes legible through response rather than labels.

### 3. Number-derived invocation crowns

Only the actively focused Sephirah gains a rotating bead crown whose bead count equals its canonical Sephirah number (1–10). The number is topological data already present in the graph, not a new correspondence claim. A fine orbit ring breathes beneath it.

### 4. Multi-current paths

Connected paths now gain a second traveling light current; a selected operative path gains a third. Direction still orients from the focused node. Ordinary unfocused edges keep the cheaper single-current treatment.

### 5. Manuscript focus choreography

The family UI now subtly yields when a node is invoked: title furniture reduces, the atmosphere responds to the active Sephirah color, register typography gains small focus motion, and the circular threshold sigil becomes more tactile without becoming a boxed control.

### 6. Fold-conscious cost control

The additional geometry is lightweight and largely only intensifies around the currently focused graph neighborhood. No post-processing pass, texture, additional Canvas, raymarch loop, or shader-kernel complexity was added.
