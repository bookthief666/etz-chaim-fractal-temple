# Etz Chaim · The Fractal Temple — M4.15 Renderer Ownership / Realm Isolation

M4.15 is implemented from the exact M4.14 source archive while treating M4.10 as the last physically accepted Fold baseline. It preserves the complete visual, mathematical, ritual, documentary, recursive, path, and Monas-family interaction system while making renderer phase ownership explicit.

## M4.15 — Renderer Ownership / Realm Isolation

- One authoritative phase model: `THRESHOLD / TREE / INGRESS / REALM / PATH / RETURN`.
- Tree, realm, and path renderers are mutually isolated. The accepted DPR-1 Tree core still preseats behind Threshold, but Tree work never runs behind Realm or Path.
- All ten Sephiroth have lazy dedicated program identities. Malkuth and Tiphareth retain their hand-authored dedicated shaders; the other eight compose selected kernels from shared math, SDF, motif, palette, and raymarch modules.
- Speculative `compileAsync` prewarming is removed. WebGL compilation begins only when the explicitly requested REALM mounts its material.
- Realm/Path atmosphere retains the full aesthetic composition as a static plate without hidden full-viewport keyframes or blend recomposition.
- Actual `webglcontextlost/restored` events are the only automatic WebGL recovery signals. Slow first light and slow ingress do not remount the Canvas.
- `?qa=1` exposes browser/GPU/frame/lifecycle telemetry and **COPY QA REPORT**; normal users receive no QA overlay or telemetry callback.
- See `docs/M4.15-RENDERER-OWNERSHIP-REPORT.md` for the exact lineage, ownership matrix, validation, and unverified physical scope.

Procedural sonification remains explicitly on hold.

## M4.14 — Solar Fast-Path / Browser Compatibility

Physical QA separated two failures that had looked similar: DuckDuckGo/privacy WebViews could delay or withhold macro-Tree WebGL first light, while a full browser could render the Tree but lose stability entering Tiphareth. M4.14 keeps those issues separate. Tiphareth now compiles through its own ~15.5 KB dedicated solar program instead of the ~40 KB ten-realm dispatcher, preserving the accepted hexagram, sixfold court, recursive stars and solar corridor while materially reducing first-entry compiler pressure. Hardened/privacy browsers receive a capability-driven quiet startup profile: default GPU selection, DPR 1 and no speculative shader prewarm. Capable browsers retain the full first-light and background-warmup path.

## M4.10 runtime lock / Malkuth compiler fast-path

- Physical QA showed a live HUD still labeled `/ M4.8` after the M4.9 handoff. M4.10 pins Vite to **5173 with strictPort**, disables dev caching, centralizes the runtime build stamp, and shows that stamp on the threshold so an older server cannot masquerade as the current build.
- React development `StrictMode` is removed from the Fold QA entrypoint so WebGL materials/programs are not intentionally remounted twice during Vite development testing.
- Malkuth now uses a dedicated ~16 KB fragment program rather than entering through the ~40 KB ten-realm dispatcher. Its crystal cells, fourfold strata/gates, tenfold rings, mineral corridor, altar, recursive inner crystal and fourfold material palette are preserved.
- Malkuth structural normals no longer evaluate the emissive glyph SDF unnecessarily; the glyph field is sampled on alternating march steps with compensated accumulation. This is a computation reduction, not a motif reduction.
